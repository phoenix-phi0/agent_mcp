# 脚本声明依赖的动词包

让 `.zs` 在开头写清楚自己要用哪些包，而不是靠调用方在外面配好。

    用包 common quiz
    # 或者 用包 common,quiz

    设 题号 = 挑题号 content/题库 1 doushi_01
    打印 {题号}

## 为什么值得

**脚本自描述**。现在一个 `.zs` 能不能跑，取决于调用方加载了哪些包——
`flows.py` 里写死了 `["common","quiz","japanese"]`，脚本自己不说。换个
地方跑就可能少个动词，而且是运行到那一行才发现。

**能关掉静默透传**。这是真正的收益。现在 `设 x = 挑题号 参数` 里动词名
打错的话不报错，变量得到字面字符串，错误一路带到产物里。声明了包之后，
引擎知道「这个脚本期望有动词」，遇到不认识的就能报错而不是当文本。

**按需加载**。不必每个脚本都扛着全部动词——`japanese` 包只有教学脚本要。

## 一、新增语句

`KEYWORDS` 加：

```python
    "用包": "use",
    "依赖": "use",
```

`_exec_stmt` 加分支：

```python
        elif head == "use":
            self._do_use(rest, lineno)
```

## 二、引擎新增两个字段

`__init__` 签名加 `verbs_root`，字段加 `strict_verbs`：

```python
    def __init__(self, client=None, workdir=None, verbose=True,
                 verbs: VerbRegistry | None = None,
                 verbs_root: Path | None = None,
                 _depth: int = 0):
        ...
        self.verbs = verbs
        # 「用包」到哪里找包目录。不给的话按 workdir/verbs 找。
        self.verbs_root = Path(verbs_root) if verbs_root else None
        # 脚本声明过包之后转严格模式：不认识的动词名报错，不当文本
        self.strict_verbs = False
```

`_sub_engine` 要把这两个传下去，否则子脚本里的动词调用会退回宽松模式：

```python
        sub = DSLEngine(
            client=self.client,
            workdir=self.workdir,
            verbose=False,
            verbs=self.verbs,
            verbs_root=self.verbs_root,
            _depth=self._depth + 1,
        )
        sub.system = self.system
        sub.temperature = self.temperature
        sub.strict_verbs = self.strict_verbs
```

## 三、`_do_use` 实现

```python
    def _do_use(self, rest: str, lineno: int) -> None:
        """用包 common quiz —— 声明这个脚本要用哪些动词包。

        写在脚本开头。声明之后转严格模式：调用不存在的动词会报错，
        而不是当成普通文本静默带过。

        包名用空格或逗号分隔都行。
        """
        names = [x for x in re.split(r"[,，\s]+", rest.strip()) if x]
        if not names:
            raise DSLError(f"第 {lineno + 1} 行：「用包」后面要跟包名")

        root = self.verbs_root or (self.workdir / "verbs")
        if not root.is_dir():
            raise DSLError(
                f"第 {lineno + 1} 行：找不到动词包目录 {root}。"
                f"创建引擎时传 verbs_root，或在工作目录下建 verbs/")

        if self.verbs is None:
            self.verbs = VerbRegistry(reserved=RESERVED)

        for name in names:
            pack = root / name
            if not pack.is_dir():
                有哪些 = ", ".join(sorted(
                    p.name for p in root.iterdir() if p.is_dir())) or "无"
                raise DSLError(
                    f"第 {lineno + 1} 行：没有动词包「{name}」。"
                    f"{root} 下有：{有哪些}")
            # 已经加载过就跳过——同一个包被父脚本和子脚本各声明一次很常见
            if name in self.verbs.packs:
                continue
            self.verbs.load_pack(pack, workspace=self.workdir)

        self.strict_verbs = True

        # 加载警告不能吞：包里的 _verbs.py 出错时，动词会静悄悄地少几个
        for w in self.verbs.warnings:
            self._emit(f"[动词包] {w}")
        self.verbs.warnings.clear()
```

## 四、严格模式：让打错的动词名报错

问题出在 `set` 分支——右侧不是已知语句也不是已知动词时，当作文本赋值。
打错动词名正好落进这一支。

```python
        elif head == "set":
            name, value = self._split_assign(rest, "设")
            sub_head, sub_rest = self._split_head(value)
            if sub_head == "call":
                self._do_call(sub_rest, lineno, assign_to=name)
            elif self._is_verb(sub_head):
                try:
                    self._do_verb(sub_head, sub_rest, lineno, assign_to=name)
                except VerbError as e:
                    raise DSLError(f"第 {lineno + 1} 行：{e}") from e
            else:
                if self.strict_verbs:
                    self._warn_unknown_verb(sub_head, sub_rest, lineno)
                self.vars[name] = self._resolve_items(value)
```

判断「这看着像不像一次动词调用」：

```python
    # 动词名的样子：不含空格、不含 { } = / \ 这些，也不是纯数字
    _VERB_LIKE = re.compile(r"^[^\s{}=/\\]+$")

    def _warn_unknown_verb(self, head: str, rest: str, lineno: int) -> None:
        """严格模式下，右侧长得像动词调用但查不到时报错。

        判据是「有参数 + 名字不含空格和标点」。单独一个词（设 甲 = 你好）
        不算——那显然是文本赋值。带参数的（设 甲 = 挑题好 3 x）才可疑，
        因为文本赋值很少长这样。

        仍然可能误判：「设 甲 = 明天 下午」会被当成动词「明天」带参数。
        所以报错信息里要说清楚怎么绕过——用 {} 包起来或者换个写法。
        """
        if not rest.strip() or not self._VERB_LIKE.match(head):
            return
        if head in RESERVED or _as_number(head) is not None:
            return
        近似 = [n for n in (self.verbs.names() if self.verbs else [])
                if head in n or n in head]
        提示 = f"，是不是想写 {'、'.join(近似[:3])}" if 近似 else ""
        raise DSLError(
            f"第 {lineno + 1} 行：没有名为「{head}」的动词{提示}。"
            f"如果这是一段普通文本，把它写成一行或用引号之外的方式避开——"
            f"严格模式由「用包」开启，去掉那行就回到宽松模式。"
        )
```

## 五、调用方改动

`flows.py` 里创建引擎时传 `verbs_root`，不再预先加载包：

```python
        engine = DSLEngine(
            c, workdir=workspace, verbose=False,
            verbs=None,                    # 让脚本自己声明
            verbs_root=verbs_root,
        )
```

但这会**破坏现有的六个流程**——它们都没写 `用包`。两种过渡办法：

一是继续预加载（`verbs=_verbs()`）**同时**传 `verbs_root`，脚本写了
`用包` 就补加载，没写就用预加载的。最平滑，但静默透传还是关不掉。

二是给六个流程都加上 `用包` 那一行。一次性改完，收益立刻拿到。

我建议第二种，六个文件各加一行：

```
# 出题：从题库里挑题
# 参数：课程、数量、考点
用包 common quiz

设 题目 = 挑题 content/n2n3/题库 {数量} {课程} {考点}
打印 {题目}
```

## 六、`dsl/run.py` 也要改

那个干净环境现在是「自动加载 verbs/ 下全部包」。改成传 `verbs_root`，
让脚本声明——正好也验证这套机制：

```python
    engine = DSLEngine(client, workdir=WORK, verbose=verbose,
                       verbs_root=HERE / "verbs")
```

`scripts/hello.zs` 开头加 `用包 common`。

## 要注意的

**误判风险**。`设 甲 = 明天 下午` 会被当成动词「明天」带参数。中文文本
里两个词之间没有标点很常见，所以这个判据不算严。真撞上了只能改写法。

保守一点的做法是只在「名字含非中文字符」或「参数里有 `{}`」时才报错——
但那样又漏掉一批真正的拼写错误。我倾向先用宽判据，遇到误判再收紧，
因为静默错误的代价比误报大。

**`用包` 必须在动词调用之前**。写在中间也能工作（那之后的调用才认得），
但那没意义，约定放开头。

**包名是目录名**，不带路径。跨目录的包不支持——那会让「这个脚本依赖什么」
变得不可预测。
