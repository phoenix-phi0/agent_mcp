# 跨次保留对话历史

现在 `对话` 的历史只活在一次 `run()` 里，脚本跑完就没了。加三条语句让它
能存盘、读回、修剪。

## 为什么是语句不是动词

历史是引擎状态（`self.history`），动词拿不到——动词只能收字符串参数、
返回结果，够不着引擎内部。跟 `重置` 是同一类。

## 为什么显式读写而不是自动

考虑过让 `对话` 带个会话名自动存取：

    对话 甲 = 今天学什么 会话=学习者A

顺手，但 `对话` 就有了隐藏的副作用——一条看着只是问模型的语句，实际上
每次都在写文件。并发、清理、什么时候落盘全成了要想的事。显式两行更笨，
但看得见。

## 一、加三个关键字

`KEYWORDS` 里加：

```python
    "读历史": "load_history",
    "载入历史": "load_history",
    "存历史": "save_history",
    "保存历史": "save_history",
    "修剪历史": "trim_history",
```

## 二、`_exec_stmt` 加三个分支

```python
        elif head == "load_history":
            path = self._safe_path(self.expand(rest.strip()))
            # 文件不存在不报错：第一次跑本来就没有历史，
            # 报错的话每个脚本都要先判断一次文件在不在
            if not path.is_file():
                self.history = []
                return
            try:
                data = json.loads(path.read_text(encoding="utf-8"))
            except json.JSONDecodeError as e:
                raise DSLError(
                    f"{self._rel(path)} 不是合法 JSON：第 {e.lineno} 行 {e.msg}"
                ) from e
            if not isinstance(data, list):
                raise DSLError(f"{self._rel(path)} 里不是消息列表")
            # 只留合法的消息，坏数据跳过而不是整个作废——
            # 历史是累积出来的，一条坏了不该让之前几十轮全丢
            self.history = [
                m for m in data
                if isinstance(m, dict) and m.get("role") and "content" in m
            ]

        elif head == "save_history":
            path = self._safe_path(self.expand(rest.strip()))
            path.parent.mkdir(parents=True, exist_ok=True)
            path.write_text(
                json.dumps(self.history, ensure_ascii=False, indent=2),
                encoding="utf-8")
            self._emit(f"[已存历史 {self._rel(path)}，{len(self.history)} 条]")

        elif head == "trim_history":
            try:
                keep = int(rest.strip() or 20)
            except ValueError:
                raise DSLError(f"第 {lineno + 1} 行：「修剪历史」后面要跟数字")
            # system 消息单独保住：它是人设，掉了模型就变个人
            sys_msgs = [m for m in self.history if m.get("role") == "system"]
            rest_msgs = [m for m in self.history if m.get("role") != "system"]
            # 从末尾留，保的是最近的对话
            self.history = sys_msgs + rest_msgs[-keep:]
```

## 三、`系统` 语句要避免重复塞 system

现在 `对话` 的分支是这样：

```python
            if not self.history and self.system:
                self.history.append({"role": "system", "content": self.system})
```

读回历史之后 `self.history` 非空，所以不会重复加——但如果存的历史里
**没有** system 消息（比如上次脚本没设系统提示词），这次设了也加不进去。

改成：

```python
            if self.system and not any(m.get("role") == "system"
                                       for m in self.history):
                self.history.insert(0, {"role": "system", "content": self.system})
```

`insert(0, ...)` 而不是 append：system 必须在最前面。

## 四、加个查历史条数的动词（可选）

放 common 包：

```python
@reg.verb("当前对话历史有多少条。用来决定要不要修剪。")
def 历史条数() -> str:
    ...
```

但动词够不着引擎状态，所以做不了。真要的话得加第四条语句 `历史条数 名`
把数字存进变量。暂时不做——`存历史` 已经会打印条数。

## 用起来

```
# 接着上次聊
# 参数：学习者

系统 你是日语教师 JP-E01-π。

读历史 会话/{学习者}.json

对话 回复 = 今天想练什么？
打印 {回复}

修剪历史 20
存历史 会话/{学习者}.json
```

`修剪历史` 放在 `存历史` 之前：存的就是修剪后的，下次读回来不会越来越大。

## 要留意的

**token 随历史线性增长**。每次 `对话` 都把全部历史发出去，二十轮之后
一次请求就要带上二十轮的内容。`修剪历史` 是必须的，不是可选的——
不修剪的话跑一周就贵得离谱。

留多少合适取决于场景。教学对话二十条（十轮）大概够，需要长期记忆的话
应该把要点提炼成一段文字塞进 `系统`，而不是留着原始对话。

**子脚本不继承历史**。`_sub_engine()` 复制 system 和 temperature，
history 是新的空列表——这是有意的，子脚本独立作用域。子脚本想接着聊
就自己 `读历史` 同一个文件。

**并发**。两个脚本同时读写同一个会话文件会互相覆盖。现在是单人本地用，
不处理；真要多人的话得按学习者分文件（上面例子里就是这么做的）。
