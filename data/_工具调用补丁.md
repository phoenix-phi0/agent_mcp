# 让模型在对话里调用动词

    用包 common quiz

    对话 回复 = {输入} 带工具 挑题,题目数,列课程 最多 3 轮
    问 答案 = 查一下 doushi_01 有多少题 带工具 题目数

引擎把动词表转成 tools schema 发给模型，模型决定调哪个，引擎执行完把结果
塞回去再问一轮，直到模型不再调工具或者到轮数上限。

跟 `agents/base.py` 那套工具循环是一回事，只是搬进了 DSL。

## 为什么轮数写在脚本里

`最多 3 轮` 是语法的一部分，不是引擎常量。看脚本就知道这次最多烧多少
token——工具调用最容易失控的地方就是「模型查了七次才收敛」，而调用方
事先不知道。写在脚本里，至少上限是可见的。

不写默认 3 轮。

## 一、顶部加正则

```python
# 带工具 挑题,题目数 最多 3 轮
TOOLS_RE = re.compile(r"\s+带工具\s+(\S+)(?:\s+最多\s+(\d+)\s*轮?)?$")
```

跟「附」一样不进 KEYWORDS——它只在语句尾巴上出现。

## 二、动词表转 schema

放在 DSLEngine 里（不放 verbs.py：这是给模型看的表示，属于调用侧）：

```python
    def _tools_schema(self, names: list[str]) -> list[dict]:
        """把动词转成 OpenAI 兼容的 tools 定义。

        参数一律声明成 string——动词签名本来就全是 str，模型给数字
        我们也当字符串收。硬要区分类型的话，得在动词里加类型标注，
        而那对动词本身没好处。

        必填与否从函数签名的默认值读：有默认值的不进 required，
        模型就知道那个可以不给。
        """
        import inspect

        tools = []
        for name in names:
            if not self.verbs or not self.verbs.has(name):
                raise DSLError(f"没有名为「{name}」的动词，无法当工具用")
            params = self.verbs.params_of(name)
            kind, impl = self.verbs.resolve(name)
            desc = (getattr(impl, "__verb_description__", "")
                    if kind == "python" else f"执行脚本 {name}")

            required = list(params)
            if kind == "python":
                try:
                    sig = inspect.signature(impl)
                    required = [p.name for p in sig.parameters.values()
                                if p.default is inspect.Parameter.empty]
                except (TypeError, ValueError):
                    pass

            tools.append({
                "type": "function",
                "function": {
                    "name": name,
                    "description": desc,
                    "parameters": {
                        "type": "object",
                        "properties": {
                            p: {"type": "string", "description": p}
                            for p in params
                        },
                        "required": required,
                    },
                },
            })
        return tools
```

**动词名直接当函数名**。中文函数名 OpenAI 规范上不合法（要求
`^[a-zA-Z0-9_-]+$`），但智谱实测能用——刚才 `zhipu_tool_test` 返回的
`get_weather` 是英文，中文的没测过。要是接口报错，这里得加一层
「中文名 ↔ 安全名」的映射表，调用时再映射回来。

## 三、按名字绑定参数

模型给的是 JSON 对象，动词是位置绑定。加个按名绑定的路径：

```python
    def _call_verb_by_name(self, name: str, args: dict) -> str:
        """按参数名调用动词。模型给的是对象，不是位置参数。

        多给的键丢掉、少给的不补——多给通常是模型自己编的字段，
        塞进去会 TypeError；少给的让动词自己用默认值。
        """
        if not self.verbs or not self.verbs.has(name):
            return f"[没有这个动词] {name}"
        params = self.verbs.params_of(name)
        kwargs = {k: to_text(v) for k, v in args.items() if k in params}
        kind, impl = self.verbs.resolve(name)
        if kind != "python":
            sub = self._sub_engine()
            sub.vars.update(kwargs)
            return sub.run(Path(impl).read_text(encoding="utf-8"))
        try:
            return to_text(impl(**kwargs))
        except Exception as e:
            # 不抛出去：工具执行失败是模型该知道的信息，让它换个参数重试，
            # 比整个脚本崩掉强
            return f"[执行失败] {type(e).__name__}: {e}"
```

## 四、工具循环

```python
    def _chat_tools(self, messages: list[dict], names: list[str],
                    max_rounds: int) -> str:
        """带工具的对话循环。messages 会被就地追加。"""
        tools = self._tools_schema(names)

        for round_no in range(max_rounds):
            data = self.client.chat_raw(
                messages, tools=tools, tool_choice="auto",
                temperature=self.temperature)
            msg = data["choices"][0]["message"]

            # reasoning_content 不能回传：推理模型会返回思考过程，
            # 原样发回去白烧 token，有的接口还会报错
            messages.append({
                k: v for k, v in msg.items()
                if k in ("role", "content", "tool_calls")
            })

            calls = msg.get("tool_calls") or []
            if not calls:
                return msg.get("content") or ""

            for c in calls:
                fn = c.get("function", {})
                try:
                    args = json.loads(fn.get("arguments") or "{}")
                except json.JSONDecodeError:
                    args = {}
                result = self._call_verb_by_name(fn.get("name", ""), args)
                self._emit(f"[工具] {fn.get('name')}({fn.get('arguments','')[:60]})"
                           f" → {result[:80]}")
                messages.append({
                    "role": "tool",
                    "tool_call_id": c.get("id", ""),
                    "content": result,
                })

        # 轮数用完还在调工具：说清楚，不要假装正常结束
        self._emit(f"[工具调用满 {max_rounds} 轮仍未收敛]")
        return messages[-1].get("content") or ""
```

工具调用**打印出来**而不是静默执行——这是 agent 最难调试的地方，DSL 这边
从一开始就让它可见。

## 五、语句接上

`_do_ask` 里，剥重试之后加一步：

```python
        rest, tool_names, max_rounds = self._split_tools(rest)
        name, prompt = self._prompt_of(rest, "问")

        if tool_names:
            msgs = []
            if self.system:
                msgs.append({"role": "system", "content": self.system})
            msgs.append({"role": "user", "content": prompt})
            result = self._chat_tools(msgs, tool_names, max_rounds)
        else:
            result = self._generate(prompt)
```

`chat` 分支同理，但 messages 用 `self.history`——工具调用的中间消息会
进历史，所以**用完通常要修剪**。

```python
        elif head == "chat":
            rest, tool_names, max_rounds = self._split_tools(rest)
            name, prompt = self._prompt_of(rest, "对话")
            self._ensure_system()
            self.history.append({"role": "user", "content": prompt})
            if tool_names:
                reply = self._chat_tools(self.history, tool_names, max_rounds)
            else:
                reply = self.client.chat_messages(
                    self.history, temperature=self.temperature)
                self.history.append({"role": "assistant", "content": reply})
            self.vars[name] = reply
            self._last_result = reply
```

注意 `_chat_tools` 自己往 messages 里追加了 assistant 消息，所以那一支
不要再 append 一次。

辅助函数：

```python
    def _split_tools(self, rest: str) -> tuple[str, list[str], int]:
        m = TOOLS_RE.search(rest)
        if not m:
            return rest, [], 0
        names = [x.strip() for x in re.split(r"[,，]", m.group(1)) if x.strip()]
        rounds = int(m.group(2)) if m.group(2) else 3
        return rest[:m.start()], names, rounds
```

## 两条路怎么选

**问JSON**：模型输出结构，脚本决定做什么。控制权在脚本，每次执行路径
一样，token 可预测。**多数场景够用**——所谓「让模型调工具」，往往真正
需要的只是「让模型填几个参数」。

**带工具**：模型自己决定调什么、调几次。控制权在模型，适合轮数事先不
知道的场合（「找出我错过三次以上的词」可能要查几轮才收敛）。

默认用前者。
