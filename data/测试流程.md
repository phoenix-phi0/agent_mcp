# 测试流程

从最浅的依赖往深处走。每一步只引入一样新东西，断在哪一步就知道是哪一层的问题。
跳步能省时间，但断了之后要回头逐层排查，反而更慢。

## 0. 环境

前置：`pip install jinja2`（只有 vue 后端需要，text / ir 后端不用）。

改了 `verbs/` 要重启服务器 —— 动词表缓存在闭包里，`reset=True` 不够。
改了 `tools/` 用 `tool_call(reset=True)` 就行，不用重启。

---

## 1. 模块能不能加载

    list_calls

逐个 import 白名单里的模块并取签名。任何一个显示 `<加载失败 ...>` 就说明那个
文件有语法错误或 import 问题，先修那个，后面都别跑。

预期：14 个符号全部带签名。

## 2. 类型契约

    tool_call  name=render.types

只碰 `render.py` 的常量，不碰 Jinja。

预期：七种类型，第三列是**语义控件名**（单行/多行/数字/日期/开关/单选），
不是 HTML 标签。出现 `input type=...` 说明改动没生效或者贴错版本。

## 3. .ui 解析

    tool_call_file  name=ui.check  path=web/demo/ui/article.ui  arg=text

只碰解析，不碰绑定和渲染。

预期：两个界面，角色分别是**表单**和**列表**（不是「自定义」——那是角色
解析错位的症状），字段数和动作数对得上，末尾提示「类型未知」。

看得更细用 `画界面`：

    dsl_run  script=设 树 = 画界面 web/demo/ui/article.ui
             打印 {树}

树里要检查的：
- 修饰词在 `[]` 里，没有漏进名字（`分组 发布设置 网個` 这类拼写错误会被
  静默吞进块名，只能靠眼睛看）
- `当=...` 原样保留
- 嵌套层级跟 `.ui` 里写的一致

## 4. 绑定与校验

    tool_call_file  name=ui.check  path=web/demo/ui/article.ui  arg=text
      args={"fields": {"title":"文本","body":"长文本",
                       "status":{"type":"枚举","required":true},
                       "published_at":"日期","featured":"布尔","slug":"文本"}}

预期：不再提示「类型未知」，没有 issue。

故意制造问题验证校验有效：字段表里删掉一个字段 → 应报「不在字段表里」；
把 `status` 的 required 改成 false → 应报「界面上标了必填，字段表里不是」。

## 5. 不带 Jinja 的后端

    tool_call_file  name=ui.compile  path=web/demo/ui/article.ui
      arg=text_or_screens  args={"backend": "text"}

预期：`files` 里有 `tree.txt`，`issues` 为空。

这一步单独存在的意义：如果它通了而第 6 步失败，问题一定在 Jinja 或模板，
不在解析和绑定。这是懒加载设计换来的排查便利。

## 6. 完整的 vue 后端

    tool_call_file  name=ui.compile  path=web/demo/ui/article.ui
      arg=text_or_screens
      args={"backend":"vue",
            "fields":{...同第 4 步...},
            "require_bind":true,
            "options":{"title":"文章管理",
                       "options_map":{"status":["draft","published","archived"]},
                       "rows":[{"title":"第一篇","status":"published"}]}}

预期三个文件：index.html、style.css、app.js。

生成的 app.js 里逐项核对：

| 看什么 | 应该是 |
| --- | --- |
| `screens` | `[{"name":"文章编辑","role":"表单"}, ...]` 角色不能是「自定义」 |
| `blank` | 按界面名分组，不是拍平的一坨 |
| v-model 路径 | 每一个都要在 `blank` 里找得到（`绑 a.b` 要有嵌套对象） |
| 枚举字段 | 出 radio，选项数量对 |
| 日期 / 布尔 / 长文本 | `type="date"` / checkbox / textarea |
| 必填字段 | 带 `required` 和红星 |
| `当 X` | `v-if="X"`，原样，没被拆成别的 |
| 布局 class | `layout row` / `region col grow` / `group grid` |

常见失败：`TemplateNotFound` —— `templates/frontend/` 里模板不全，
需要五个：index.html.j2、style.css.j2、app.js.j2、layout.j2、widgets.j2。

## 7. 走动词（agent 将来走的路）

    dsl_run  script=设 字段 = title:文本,body:长文本,status:枚举
             设 结果 = 生成界面 web/demo/ui/article.ui web/demo/frontend {字段}
             打印 {结果}

跟第 6 步做的是同一件事，但经过 DSL。两条路结果应该一致；不一致说明动词层
的参数转换有问题（字段表的两种写法、路径校验、选项表 JSON 解析）。

注意 DSL 参数按空格切分，字段表和选项表都不能带空格，要先用「设」存变量。

## 8. 打开看

把生成的三个文件放同一目录：

    python -m http.server

浏览器打开 index.html（Vue 从 CDN 拉，要联网）。

点一遍：切界面、勾「是否推荐」看短链字段出不出来、列表点「编辑」看跳不跳
回表单并带上那行数据。控制台看 `onSubmit` 的日志。

## 9. 回归

    run_tests

DSL 引擎自己的测试，跟上面几层无关，但改过 `tools/` 之后值得跑一次确认
没碰坏别的。预期 100 通过 0 失败。
