## 找重构点的清单（每个文件都过一遍）
- 重复：两处以上几乎一样的代码块（鉴权、参数校验、写流水、回滚处理）。写出各自的位置和大致行数。
- 过长：单个函数超过 60 行、或者一个函数里做了好几件互不相干的事。
- 过大：单个文件超过 400 行、混着几层职责（存储、业务规则、校验）。
- 命名：名字和实际做的事对不上；同一个概念在不同地方叫法不同。
- 魔法值：错误码、上限、默认值散落成字面量，没有集中定义。
- 难测：只能靠 monkeypatch 内部细节才能测的地方；测试钩子散落、位置不统一。
- 死代码：没有调用方的函数、永远走不到的分支（先 grep 确认没人用）。

## 风险怎么判
- 低：纯搬移、改名、提取常量，测试能直接证明没变。
- 中：合并重复的校验或鉴权代码，错误码的先后顺序可能被打乱。
- 高：动到事务边界、锁、并发路径、错误码判定顺序。这类要在 suggestion 里写清怎么保住原行为。

## 写法样例
```
location: wallet_service.py:WalletService.deposit / transfer（第 210–240 行、第 300–335 行）
problem: 两个函数开头各自重复一段「_authenticate → 校验 amount 是 int 且在 1..10^12」，约 25 行几乎相同
impact: 改金额规则要改两处，已经出现过一处漏改的风险
suggestion: 抽成 _check_amount(amount)，两处调用；判定顺序不变（先鉴权后校验）
risk: 中
```
