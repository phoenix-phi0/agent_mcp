## 读代码的顺序
1. 先看实现记录的 changes，知道这次改了哪些文件、哪些函数。
2. 按清单逐条找入口函数，顺着调用读到底：参数校验 → 主逻辑 → 写库或返回 → 错误分支。
3. 对照约定（签名、返回、错误码、错误的先后顺序）。

## 常漏的地方
- 错误分支：空值、不存在、重复、越权、超长；多个错误同时成立时先报哪个。
- 边界：恰好在上限、差一、空列表、最后一页。
- 状态：事务有没有包住所有写操作，失败时有没有回滚干净；并发两次提交会怎样。
- 资源：文件、连接、子进程有没有关；超时有没有处理。
- 和约定不一致：名字、参数顺序、返回字段、错误码拼写。

## 依据的写法
- 好：`{"出处": "app/orders.py:88-90", "原文": "if qty <= 0:\n    raise OrderError('BAD_QTY')"}`。
- 不行：`{"出处": "orders.py", "原文": "校验了数量"}`——没有行号，原文是转述。
