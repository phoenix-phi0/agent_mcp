## 归因的判断
- 我的改动：失败的那一行，或它调用的函数，在这次改动清单的改动块里；或者这次改了接口、调用方没跟着改。
- 别人的改动：引起失败的改动在 git diff 里，但不在这次的改动清单里（清单标了「范围外」或「归属不明」的那些）。
- 环境：报错是 ModuleNotFoundError、连接拒绝、端口被占、缺少 API Key、权限不足、超时；代码没变。
- 测试本身：断言写死了时间或顺序、依赖上一个测试留下的数据、单独重跑能过。
- 原来就有：在基线的失败列表里。

## 原因的写法
- 好：「test_transfer_limit：期望 LIMIT_EXCEEDED，实际成功；app/wallet.py:142 把 `>` 改成了 `>=`，这一行在这次改动块里」。
- 不行：「转账逻辑有问题」。

## 建议的写法
写清交给谁、改哪里：「交给这次的工程师：app/wallet.py:142 改回 `>`，或改约定后同步改测试（要架构师裁决）」「交给人：测试环境缺 redis，装上再重跑」。
