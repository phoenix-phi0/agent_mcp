# agent_mcp 编排查看器（VS Code 插件）

在本机 VS Code 里看流程管理（`tools/wf_mcp_server.py`）的运行，不用 SSH，也不用开浏览器。

## 安装

1. 拿到 `agent-mcp-trace-0.2.0.vsix`（在本目录运行 `npx @vscode/vsce package` 生成）。
2. VS Code 命令面板：「Extensions: Install from VSIX…」，选这个文件。
3. 左边活动栏出现「编排运行」，点「连接查看器」，粘贴查看器链接，如
   `https://ali-demo.yscinternet.top/trace/<口令>/`。口令存在 VS Code 的加密存储里，设置里只记地址。
   本机起的服务（`python -m tools.trace_server …`）填 `http://127.0.0.1:8765/`。

## 能做什么

- 侧边栏按「等确认 / 运行中 / 出错、中止、中断 / 完成」分组列出运行，默认 5 秒刷新（设置 `agentMcp.refreshSeconds`）。
- 点一项打开运行页：概况、分配清单、耗时、流程图和节点详情，和网页上的一样；批准、驳回、改计划也能在这里做
  （服务端开了写接口时）。深浅色跟着 VS Code。
- 有运行新停下来等确认时弹通知（设置 `agentMcp.notify` 可关），状态栏常驻「⏸ N 个待确认」，点一下直接打开。
- 节点详情底部「脚本原文」旁边有「在编辑器里打开」：把这次运行的流程脚本开成只读文档，跳到这个节点那一行。

## 自己写实现步骤的代码

实现步骤（格式是实现记录、角色有工作目录，如 ENGINEER）停下来等确认时，运行页上有「拉到本地」「从 VS Code 交代码」，
侧边栏的等确认项右边也有这两个按钮（命令面板里是「编排：拉取实现步骤的工作目录到本地」「编排：交代码」）。

1. **拉到本地**：选一个空文件夹，服务器把这一步工作目录（如 `work/demo`）里的文本文件给过来，插件写进去，
   用 git 提交成基线（本机要有 git）。文件夹里的 `.agent-mcp-run.json` 记着它对应哪次运行，不进 git。
   虚拟环境、缓存、`.env` 和密钥文件、二进制、超过 1MB 的文件不拉。
2. 在本地改代码。
3. **交代码**：插件和基线比，列出新增、修改、删除的文件让你勾选，再填摘要、遗留问题、完成状态，交给服务器。
   服务器把文件写进工作目录，跑这次流程设好的测试命令（`test_cmd`，请求里不能指定），按实际改动生成实现记录：
   - 开始前确认的步骤：不调模型，记成外部结果；
   - 结束后确认的步骤：保留模型那次的改动，叠上你的，算「改了再通过」。
   测试没过时服务器把文件撤回、不提交，测试输出在「agent_mcp 编排」输出面板；可以选「仍然交」（状态记为部分完成）。
   交成功后本地基线前移，接着改接着交。

以后的步骤又停在实现上时，在同一个文件夹再「拉到本地」会同步成服务器上的样子（要先把没交的改动处理掉）。

## 安全

- 运行页放在 Webview 里，不直接连网；页面的请求交给插件去发，而且只放行
  `api/runs`、`api/run`、`api/plan` 这三个读接口和服务端的几个写接口，别的地址一律拒绝。
- Webview 的内容安全策略不许连任何外部地址。
- 拉工作目录（`api/workfiles`）和交代码（`api/submit_files`）由插件自己发，页面发不了；查看服务只读时两个都拒绝。
  服务器只写这一步的工作目录：路径越界、经过符号链接、写进 `.git` / `.venv`、密钥类文件都拒。
