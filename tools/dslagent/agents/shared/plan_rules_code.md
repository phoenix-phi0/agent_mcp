- 改法：已经读到原文的改动
  - 原文抄进 #改法 段；脚本里 设 res = 改文件 {e1}，合成一段一次套；互相独立的大块可分 e1、e2
  - 如果 {res.ok} 不等于 是：把 {res.msg} 带进一次 派任务（入参给那段「文件:起-止」）让它重给 edits，再 改文件 {r.result}；还不行就 终止 失败
- 子任务：没读到原文、或要看运行结果才能决定怎么改的
  - 用 派任务，入参「文件:起-止」；格式 edits:列表,note:文本；逻辑里写明 edits 字段名 file / old / new，old 从入参原文照抄，以及新模块的函数签名和 import 写法
  - 拿回后 设 res = 改文件 {r.result}；互不依赖的用 并行派任务（结果是列表，遍历逐个 改文件）
- 「收敛 / 统一 / 替换所有 / 改用 / 去重」这类任务
  - 先用 搜索代码 / 查引用 把所有位置找全；脚本必须覆盖找到的每一个位置，#清单 逐文件列出
  - 位置分布在 ≥ 3 个文件时：新模块先用 #改法 建好，再按文件 并行派任务（每项 1–2 个文件，总数 ≤ 8），任务描述写明新模块的函数签名、行为和 import 写法
- 旧写法（可选）：在 用包、预算 之后用注释逐行写 # 旧写法: <Python 正则>
  - 只匹配「改完后不应再出现」的旧实现（被替换的手写判断、被删的旧函数定义）；不能匹配新写的调用、注释或无关代码
  - 验收时在任务涉及目录（不含测试和新建文件）搜残留，有残留派补改，仍有判失败；没有可核对的旧写法就不写
- #清单 必须写：逐行 改 路径:函数名 / 新建 路径 / 删 路径，列出这次要动的全部文件
- 任务明显限定在某个目录时，#清单 之后另起一行 #范围，下面每行一个允许改动的目录前缀（如 kg/、tests/kg/）；范围外的改动会被恢复并要求补改。没有明确限定就不写
