## 期望表（附加要求，是上面「输出」只出 .zs 的唯一例外）
计划（.zs）写完之后，在最末尾另起一段，输出标题行 `#期望表`，下面紧跟一个 JSON 数组（可用 ```json 围栏），供程序在改完后按表调用函数核对结果：
[{"规则": "任务原文里的原话", "函数": "函数名", "参数": {参数名: 值}, "断言": [ {类型: 参数}, … ] 和/或 "期望": 返回值 / "期望包含": "子串" / "期望异常": "异常类名或信息片段", "文件": {相对路径: 文本内容}（可选）}]
每项至少有「断言」「期望」「期望包含」「期望异常」之一；「期望」「期望包含」「期望异常」三者之间只写一个，「断言」可与其中一个并存。

### 断言词表（程序判定，列表里全部满足才算过）
返回值先被预处理成「项列表」：字符串→按行切开（去空行）；列表→原样；字典→只含它自己的单元素列表。
- {"条数": {"≤": N}}（也可用 "=" 或 "≥"）：项数的关系。
- {"都不含": ["子串", …]}：每一项的文本都不含这些子串中的任何一个（例如 {"都不含": ["venv/", ".git/"]}）。
- {"都含": "子串"}：每一项都含该子串。
- {"有含": ["子串", …]}：每个子串至少在某一项里出现。
- {"都匹配": "正则"}：每一项完整匹配该正则。
- {"字段都在": {"字段": "status", "取值": ["done","failed"]}}：每个字典项的该字段值属于集合。
- {"有序": {"字段": "id", "方向": "降"}}（"升"/"降"；字段写 "行" 表示按整行文本比较）。
- {"行号连续": {"从": 1}}：每行开头是「数字| 」前缀，依次为 从, 从+1, …。
- {"不抛异常": true}。
- {"同改前": true}：程序在改之前的代码上用同样输入也调用一次，结果必须与改后完全相同。
- {"类型": "str"}（str / list / dict / int）。
「都不含」「都含」「有含」「都匹配」可以带字段：{"都不含": {"字段": "id", "值": ["k1"]}}，表示只检查字典项的该字段。
示例：
{"规则": "<原文>", "函数": "列文件", "参数": {"path": "."}, "断言": [{"都不含": ["venv/", "node_modules/"]}, {"有含": ["a.py", "venv2/y.py"]}]}
{"规则": "<原文>", "函数": "读文件", "参数": {"path": "normal.txt"}, "断言": [{"条数": {"≤": 10}}, {"行号连续": {"从": 1}}]}
{"规则": "<原文>", "函数": "读文件", "参数": {"path": "short.txt"}, "断言": [{"同改前": true}]}

### 要求（程序会逐条检查，不够会退回让你补）
0. **能用性质表达的规则优先写「断言」，不要手算完整结果**（手算容易算错，一条写错的项会让正确的实现被判不通过）。只有结果很短、能从任务原文和夹具直接确定时才写「期望」。「保持不变」「照旧」类规则优先用 {"同改前": true}（再配合需要的性质断言）。
1. 任务原文里每一条明确的规则都要进表，至少一项：分情况、默认值、报错/提示文字、边界值、上限、筛选条件、跳过名单（逐个名字）、「保持不变」「照旧」「不抛异常」之类。一句话里有几条规则就写几项。「规则」字段必须原样抄那句任务原文（连续抄原文，不要改写、不要概括）。
2. 每个函数至少写一项反向用例：不应出现什么、不应改变什么（用「都不含」「字段都在」「条数」等断言表达）。
3. 输入要能区分正确与错误实现：默认值类规则（如缺省 10）要用行数/条数大于默认值的夹具（normal.txt 有 20 行，short.txt 只有 3 行，测默认值要用 normal.txt）；上限类规则要让夹具条数超过上限（用小的上限值，如 limit=3，或用条数多于缺省上限的夹具）；有「按 X 筛完再取上限」这类先后顺序的规则，要构造筛选命中数多于上限的输入；边界要测边界两侧各一个值。
4. 允许并鼓励为任务要求「保持不变」的、没有改动的函数写项（只要这个函数在改完后的代码里真实存在；动词写动词名，模块函数写「文件路径::函数名」）。「同改前」只用于行为确实不变的函数；任务要求改变行为的函数不要写同改前。
5. 「函数」和「参数名」必须是改完后真实存在的名字，必填参数都给；动词的参数值一律写成字符串；模块函数的参数用 JSON 值，pathlib.Path 写 {"$Path": "路径"}。
6. 断言的子串/数字必须能从任务原文加下面的夹具说明确定地推出，拿不准就不写这条断言，但宁可多写几项也不要只写两三项。没有异常就不要写「期望异常」。
7. 表条数的下限：每个要改的函数至少 2 项，整体通常 8–20 项。
可用夹具（工作区固定文件，每次调用前现造）：empty.txt（空文件）；short.txt（3 行：a1 / a2 / a3）；normal.txt（20 行：line1 … line20）；sub/inner.txt（2 行：in1 / in2）；link_in.txt（指向 normal.txt 的符号链接）；link_out.txt（指向工作区外文件的符号链接）；项目树（每个文件内容是 X = '<相对路径>'）：a.py、.hidden.py、pkg/__init__.py、pkg/m.py、sub/mod.py、sub/.x/y.py，以及 venv/ venv2/ build/ builds/ dist/ env/ node_modules/ site-packages/ __pycache__/ .git/ 各有一个 .py（x.py y.py b.py c.py d.py e.py n.py s.py p.py g.py，依次对应 venv venv2 build builds dist env node_modules site-packages __pycache__ .git），sub/venv/z.py、sub/build/w.py；工作区外有 outside.txt（2 行：out1 / out2），写作 $OUT；$WS 表示工作区绝对路径。
需要别的文件时，在该项里加可选字段 "文件": {相对路径: 文本内容}。动词按名字调用，参数都是字符串，相对路径相对工作区。个别模块有专用夹具，要改的文件涉及它时，说明会附在用户消息的「专用夹具说明」里。
8. 表里的内容不要影响 .zs 本身的写法。
