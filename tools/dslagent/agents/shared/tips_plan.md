## 输出前自检（心里做，不输出过程）
先列要点（要改的函数、边界情况、决定，≤10 项），每个决定只做一次，不反复重写草稿；写完逐条核对：
1. 每条语句只占一行；问 / 问JSON / 派任务 的提示词里不能换行（换行后的半句会被当成新语句判错），分段用「；」或「|」，「格式 …」写在同一行末尾；派任务 最多 4 个参数（任务 入参 逻辑 格式），带空格的值先 设 成变量，再写 {变量}
2. 每条 设 x = … 的右边：首词（第一个空格前）不是白名单动词时，必须整段不含空格，或首词带「：」或是 {变量}；整句中文说明写成一行带空格也一样会被当动词，报「没有名为…的动词」
   - 错：设 code = import tempfile, os　设 h = 改 foo 为 bar　设 d = 只改 a.py　设 n = 根因 在 catalog 里　设 m = from os import path　设 w = 修改 两个批量执行器的签名　设 k = 创建 新文件并补测试　设 j = 将 a 与 b 合并
   - 对：设 code = t=0;import os;print(1)　设 h = 线索：改 foo 为 bar　设 h = {d.reason} 待核实
3. #改法 里的原文逐字抄自读到的片段：含缩进，不带「  12| 」行号前缀，在文件里唯一；整个函数重写用「@@ 改 路径 函数 名」只写新函数，不抄原文；#改法 段内只允许 @@ 行与 <<<<<<< ======= >>>>>>> 块，不放语句、JSON、说明、围栏
4. 第一行 用包 common text code，第二行 预算 调用 N 秒 M（N 是 1–12 的正整数，不能写 0；M ≤ 600）
5. 要模型给 edits 时，提示词里写明「每项字段名固定为 file（相对路径）、old、new」；模型看不到代码也不记得前面的调用，要它看的内容先用动词读出来嵌进提示词
6. 脚本末尾顺序：#改法 → #清单 →（#范围）→ #期望表；#改法 / #清单 之间和之后不再写脚本语句
