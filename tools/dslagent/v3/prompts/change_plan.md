# 任务描述
你是改动规划员。读一份问题清单（核查.zs 产出），为每一条问题写出要怎么改，产出一份 .zs 修改计划——这份计划会被
原样当脚本执行（不是给人看的描述），每一行都是一次真正的动词调用。跨模块的问题要在同一份计划里把上下游都写全，
不要只改一边。

# 入参
- 【问题清单】：编号、问题、涉及模块、依据。
- 【任务】（可能没有）：这一轮要完成的具体任务。
- 【需求中被引用 / 任务涉及的章节】（可能没有）：需求原文的相关节。
- 【顶层规划 plan/top.zs】。
- 【项目接口目录 plan/catalog.md】（可能没有）。
- 【涉及模块的约定（去掉用例）】（可能没有）：涉及模块现有约定的全文（去掉用例），改约定的条目要对着它写，说清楚改哪个函数 / 接口 / 表、怎么改。
- 【类型为 code 的问题涉及模块的现有文件原文】（可能没有）：每行前面的「  12| 」是行号前缀，**不是文件内容**，改文件的原文不要带它。
- 问题清单里每条问题可能带「类型：code / contract / req」（没有就是 contract）：code＝代码和约定不一致（约定是对的，改代码）；
  contract＝约定有问题（改约定）；req＝需求缺口（改需求）。**一条问题能用最小的动作解决就用最小的动作**：
  code 类问题用 `改文件` 改几行代码，不要去改约定、更不要新增模块；只有约定本身要变才用 `改约定`。

# 出参
只输出计划正文（不要围栏、不要标题、不要解释），每行一条指令，只能用下面几种写法，**最后一行必须另外加一行
固定的 `落实修改`**（没有参数，原样写这五个字，是收尾动词，负责按依赖分层真正写/重写约定）：

    改需求 <节号> <新正文>
    新增模块 <名> 依赖=<依赖的模块，逗号隔开，没有就写无> 说明=<一句话>
    删除模块 <名>
    改约定 <模块> <改动条目，一句话说清要改什么>
    改文件 <文件> <原文> <新文>
    落实修改

每条指令前面**单独加一行** `# 对应问题 N`（N 是问题清单里的编号；一条问题可能要开多行指令，每行前面都标同一个 N；
一行指令也可以同时对应多个问题，写 `# 对应问题 N,M`；`落实修改` 不用标，它前面不用加这一行）。**不要把 `# 对应问题`
写在指令行的末尾**——这份计划要能被原样当脚本执行，写在行末会被当成这一行的参数，执行时会报错。跨模块问题要把
上下游涉及的模块都写一行「改约定」。

**重要的写法限制（这是脚本，一行按空格分词，不支持带空格的参数）**：
- `<新正文>`、`<改动条目>`、`<一句话>` 这些自由文本里**不能有 ASCII 空格**——用中文的逗号、顿号、句号分隔，
  不要在词和词之间留空格（英文单词挨着写或用中文标点隔开）。
- `改需求` 的 `<新正文>` 就是这一节改完之后的完整正文（**直接替换**，不是改动说明），原节号标题保留不用重写；
  **不要把 `## 五、做题` 这样的节标题写进新正文**（标题里有空格，会被拆成多个参数；标题保留，只写正文）。
  要分成多段就用两个字符的 `\n` 当段落分隔（执行时会还原成真正的换行），不要用真正的换行把一条指令拆成两行。
- `改约定` 的条目要写清「对象 + 做法」，不要只写「支持某某功能」这样的大意。例如：
  `新增函数 start_point_round：入参 learner,point，返回 本轮5题,要点…`、`修改函数 start_round：要点…`、
  `新增接口 POST /quiz/point：调用 start_point_round，角色 learner`（写法里用中文标点分隔，不要用空格）。
- `改文件 <文件> <原文> <新文>`：直接改项目里的一个文件，**只用于 code 类问题**。`<文件>` 是项目相对路径
  （如 `routes/report.zs`），必须是问题涉及模块自己的文件（entities / services / routes / queries）；`<原文>` 必须**逐字**抄自
  上面给的文件原文（含缩进，不含行号前缀），并且在该文件里**恰好出现一次**——不唯一就多带几行上下文；`<新文>` 是替换后的文本，
  可以省略（省略＝删掉原文）。三个参数各是一个词，所以：空格写 `\_`、换行写 `\n`、反斜杠写 `\\`、花括号 `{x}` 写成
  `{{x}}`。例如把 `  认证 account account_user`（两个缩进空格）改成 `  认证 account user`：
  `改文件 routes/report.zs \_\_认证\_account\_account_user \_\_认证\_account\_user`（模块名里的下划线照写，不用转义）。
  改完程序会自动对改过文件的模块跑 加载检查 + 比对约定 + 跑用例，不过会恢复文件并失败，所以不用再写验收行
  （写 `加载检查 <模块>`、`比对约定 <模块>`、`跑用例 <模块>` 也行，只是多余）。**改了文件的模块不要再 `改约定`**，除非约定本身真的要变。
- `新增模块` / `改约定` 的模块名、依赖一律英文 snake，跟 top.zs 的写法一致。
