## 项目 DSL 写法说明（只讲项目代码怎么写、引擎支持什么；以下以引擎实际解析为准）

项目目录：entities/*.entity（建表）、queries/*.sql（一个文件一条 SQL）、services/<模块>.zs（业务逻辑）、routes/*.zs（HTTP 接口 + 项目级声明）、contracts/（约定，只读）。

### 实体 entities/<模块>.entity
```
实体 answer 作答
  字段 learner 文本 必填 索引 学习者
  字段 correct 布尔 必填 默认 否 对错
结束
```
类型：文本 长文本 整数 小数 日期 布尔 枚举（枚举 a,b,c）；旗标：必填 唯一 索引；`关联 <实体>`、`默认 <值>`、`主键 a b`、`唯一 a b`。一个实体 = 一张表，隐含自增 id（写了 主键 就不加）；每个实体以「结束」收尾；只写本模块拥有的表。约定要求某字段唯一时，实体里**必须写 `唯一` 旗标**（如 `字段 code 文本 必填 唯一 编号`；多列合起来唯一用行首 `唯一 a b`）——「唯一」只写进字段说明文字不生效，建表不会加 UNIQUE，库不拦重复。核查时缺旗标算 module_issue（代码里先查后插也算：并发请求、绕过业务层直接写库都不受这个旗标保护）。

### 查询 queries/<名>.sql
一个文件一条语句，参数 `:名`；参数传进来都是字符串，数值比较 / LIMIT 要 `CAST(:n AS INTEGER)`；文件名以模块名开头。

### 业务层 services/<模块>.zs
文件第一句必须是 `业务 <模块名>`，模块名等于文件名（不带点）；块内只能写 `依赖`、`用包`、`[公开] 函数`，最后「结束」，「结束」之后不能再写东西。
```
业务 progress
  依赖 graph
  用包 db
  公开 函数 记作答 learner point_code answer?
    设 p = 调用 graph.取知识点 code={point_code}
    如果 {p} 为空
      报错 404 没有这个知识点
    结束
    事务 app.db
      设 n = 写库 app.db progress_answer_insert learner={learner} point_id={p.id}
    结束
    返回 {"ok": 1}
  结束
结束
```
- 函数独立作用域，只有入参；`名?` 是可选入参，不传是空串；函数名不能带点、不能重复。
- 调用：`设 r = 调用 模块.函数 键=值 …`（同模块可只写函数名）。必填参数必须给，不认识的键报错；只能调公开函数（同模块除外）；跨模块调用必须在调用方业务文件里写 `依赖 <模块>`；不能依赖自己、依赖不能成环、依赖的模块必须存在（否则服务拒绝加载）。
- `报错 4xx 文字` 是业务错误，沿调用链变成接口的 HTTP 码 + {"error": 文字}；调用尾部加 `出错时 e` 接住（`{e.code}` `{e.error}`，没出错 `{e}` 是空串）。模型返回的内容不合格（问JSON 格式不对：不是合法 JSON、缺字段、类型不对）也算这类，`出错时` 一样接得住（`{e.code}` 是 502）；模型调用本身失败（超时、限流、服务不可用、网络断）也接得住（`{e.code}` 是 503，`{e.error}` 带「模型调用失败：」前缀和原文）；脚本写错、引擎内部错、加载错不会被接。问JSON 语句自己也能接：在语句**末尾**写 `出错时 e`（`问JSON j = 提示词 格式 a:文本 b?:数字 出错时 e`；没有「格式」就 `问JSON j = 提示词 出错时 e`），接住时目标变量是空串；`出错时 <变量>` 只认语句末尾这个位置，写在中间会被当提示词文字（加载检查报「问JSON 的 出错时 要写在语句末尾」）。
- db 包动词：`查一行`（没有则空）、`查一值`、`查询`（多行列表，可 遍历）、`写库`，写法 `动词 app.db 查询名 键=值`（键=值 最多 8 对）。值的空格规则：值是**字面量**时不能带空格——会被按空格切开，后半截被当成下一个参数，引擎直接报错；值整个是 `{变量}` 时，变量**内部**的空格 / 换行原样保留、没有问题（核查时「`键={变量}` 且变量可能含内部空格」不算问题）；值**首尾**有空白引擎直接报错（传给 SQL 前会被剪掉，存进去的跟原值对不上）；字面量值里带「词=值」碎片会多出 SQL 用不到的参数，引擎也报错。值要保留首尾空白、或要传整条记录 / 参数超过 8 对时，用 `查询表` / `查一行表` / `查一值表` / `写库表`（与前四个一一对应，写法 `动词 app.db 查询名 {结构}`，参数从一个结构（如 `{request}`、`{表单}`）里按名取，不按空格切，没有 8 对的限制；`写库表` 返回影响行数）；查询名 = queries/ 下文件名（不含 .sql）；几个写操作要一起成败包在 `事务 app.db … 结束`。
- 内容文件：模块可以把**本模块的源数据**存成 `content/<本模块名>/` 下的 JSONL / JSON 文件（文件是源，库是它的投影，所以必须提供「按文件重灌」的函数）。业务文件顶部的 `用包` 行要带上 data（如 `用包 db data`）；能做的只有 data 包的 `写JSONL 路径 {列表}` / `写JSON 路径 {结构}` / `删文件 路径` / `移动文件 源 目标`（tools 的 verbs/data/_verbs.py:146、155、168、181，路径限工作目录内：同文件 :38-47 `safe`；移动文件父目录自动建、目标已存在覆盖、源不存在返回「否」、源是目录报错），读用 `读JSONL 变量 = 路径` / `读JSON 变量 = 路径`（引擎语句，tools/dsl.py:1468 起，路径限工作目录：tools/dsl.py:525-529）、`存在 路径`（verbs/data/_verbs.py:100）。规则（加载检查会查）：
  1. 写 / 删 / 移动（源和目标都算）的路径必须直接写成以 `content/<本模块名>/` 开头的字面量（变量只能放在后面，如 `content/lesson/{series}/items.jsonl`，只核 `{` 之前的前缀；整个路径是变量不行）；不写别的模块的目录、不写 content/ 以外的路径；只写 JSON / JSONL（后缀 .jsonl / .json），不写 md / 文本 / 导入文件（没有这种动词）。
  2. **不读别的模块的 content/**（也不写）：跨模块传数据一律调对方的公开函数（跨模块调用要 `依赖`）。
  3. 约定里要有 `## 内容文件` 段声明每个路径（格式见约定提示词）；函数里用到的 content 路径都要在那里有声明（比对约定会查，没声明算不一致）。
  4. 模板——保存：函数先 `写JSONL content/<m>/<名>.jsonl {rows}`（文件为准），再在 `事务 app.db … 结束` 里先清空本模块的表、再按文件内容逐行写库（这一步写成公开函数「按文件重灌」，保存函数调用它，也可以单独调用）；撤下 / 删除：把文件挪到 `<名>.withdrawn.jsonl`（`移动文件 content/<m>/x.jsonl content/<m>/x.withdrawn.jsonl`）+ 清库；读列表仍从库读。
  5. 验收用例照常 `调用`，不新增用例语句：文件内容用本模块的**公开读回函数**核对（如 `读回卡片` 读 `读JSONL` 返回条数 / 内容，文件不存在时返回约定好的值），库用「库 …」核对。跑用例在临时 workspace 里跑（packs/dslproj/cases.py `run`：`copytree` 到临时目录），content/ 写在那里，不会写进项目；每个用例开始前会清空本模块及上游的 content/<模块>/（`reset_content`），所以一个用例要的文件由它自己的「先 调用 …」造出来。
- 除内容文件外业务层不写盘：没有写任意文件（md / 文本 / 导入文件 / 别的目录）的动词，不要拿 写JSON / 写JSONL 中转业务数据；需要把数据交给别的模块时，调用对方的公开函数传数据，不要靠写文件中转。
- 条件：等于 不等于 为空 不为空 包含 不包含 大于 小于 不小于 不大于 开头是 结尾是；组合 且 或 非。`{x 或 默认}` 取变量空时用默认。
- 后台任务：`后台执行 scripts/<m>_<名>.zs 键=值 on_error=scripts/<m>_<名>_fail.zs` 能在业务函数里用（只认已有的 .zs 脚本，不能后台跑函数；引擎实现 tools/dsl.py:1283 `_do_call_bg`；子引擎沿用调起方的服务层和模块，tools/dsl.py:557-575）。模块拥有 `scripts/<模块>_*.zs`（文件名以「<本模块名>_」开头，同前缀模块取最长归属），只有约定写了 `## 脚本` 才写这些文件。模板：
  1. 业务函数里先写库建好任务行 / 块行（状态=待处理），**在事务结束之后**再 `后台执行 scripts/<m>_<名>.zs id={id} on_error=scripts/<m>_<名>_fail.zs`（后台线程独立于请求事务，参数是深拷贝，tools/dsl.py:1318、1339；写在 `事务` 里面可能事务还没提交任务就开跑），随后返回任务 id。
  2. 脚本只做编排（遍历、调函数），读写状态都调本模块的函数（`调用 <m>.函数 …`，子引擎沿用调起方的模块，tools/dsl_service.py:36-39）；**脚本里只能调公开函数**，私有函数只有业务函数里能调（tools/dsl_service.py:341-346，调了报「不是公开函数」，加载检查也会报），所以给脚本调的函数要写成 `公开 函数`（不配接口就只有本模块脚本用）；脚本里不要直接写业务 SQL。
  3. fail 脚本把状态写成失败并记 `{error}`（比主脚本多一个 error 变量：出错的一句话原因，tools/dsl.py:1339-1356）；不写 on_error，出错只打日志，页面上看不到。
  4. 后台里没有请求上下文，「响应」「消息」不起作用，结果只能写库，前端轮询另一个公开函数（接口仍只调一个函数）。
  5. 本模块的脚本只由本模块的函数 `执行` / `后台执行`，别的模块只能调公开函数。
  6. 验收用例照常 `调用` 提交函数，跑用例每次调用后会等后台任务跑完（packs/dslproj/cases.py:52-58），再核对库。

### 接口 routes/<模块>*.zs（文件名以模块名开头）
```
接口 POST /progress/answer 动作 answer 公开 角色 teacher
  设 r = 调用 progress.记作答 learner={learner} point_code={point_code}
  返回 {r}
结束
```
- 接口行格式：`接口 [GET|POST|PUT|DELETE] /路径 [动作 名] [公开] [角色 代号 | 只许 中文名]`，方法省略 = POST；「公开」「角色」「只许」都可省。同一方法 + 路径不能重复声明；同一动作名不能被两个接口声明。
- 接口里只收请求、调约定里写的那个函数、返回。请求体 / GET 查询参数直接是变量（`{learner}`），没传是空串。
- **路径是死字符串，不支持 `{参数}` 路径参数**：请求按「方法 + 请求路径」原样精确匹配，`DELETE /notes/{note_id}` 只会匹配字面路径 `/notes/{note_id}`，真实请求 `/notes/5` 回 404「没有这个接口」。要传 id 就用请求体 / 查询参数（如 `DELETE /notes/delete`，id 从 `{note_id}` 字段取）。
- 接口只能调公开函数；接口文件属于哪个模块按文件名前缀（取最长的），可调本模块全部公开函数，调别的模块要本模块业务文件依赖它。

### 认证声明（写在 routes/ 任一 .zs 顶层、接口块外面；对整个项目生效，不是某个文件的事）
- `认证 必须`：一直要登录；只有标了「公开」的接口不登录也能调，其余未登录回 401「请先登录」。
- `认证 可选`：平时不要登录；启动时开了登录才等同「认证 必须」。
- 没有「认证 必须」也没有「认证 可选」时，启动时开登录会报错；此时「公开」「角色」都不起作用。
- `认证 核对 <库> <查询名>`（旧写法，两个参数）：每个请求认出 cookie 里的人后，在工作区的库文件 `<库>`（是文件名，如 app.db，不是模块名）里跑 queries/<查询名>.sql（参数 `:username`）；查不到 = 当没登录；查到的行里 `role` 列成为当前角色。库路径、查询不能越出工作区，查询文件不存在报错。
- `认证 核对 <模块>.<函数>`（新写法，单个参数且含点号）：每个请求认出人后，调业务函数 `<模块>.<函数> username=<用户名>`，函数必须是该模块的**公开函数**且有入参 `username`。返回非空对象 = 用户信息（其 `role` 字段成为当前角色）；返回空或报 404 = 当没登录；函数不存在 / 不是公开 / 其它出错 / 返回的不是对象 → 请求回 500。
- 「核对」的两种写法只能写一种；同一种声明（核对、身份）写了不同的几行会报错。写成 `认证 核对 account account_user` 这样「模块名 + 查询名」，会被当成旧写法：库=account（不是库文件），不会去调业务函数。
- `认证 身份 <变量> 默认 <值>`：开着登录时，请求里该变量（含 `{request.<变量>}`）一律被登录用户名盖掉，前端伪造无效；没开登录时取请求体里的值，空则用默认值。
- 约定（contracts/）里不写认证行，认证块由程序在账号模块 routes 里生成；账号模块提供公开函数 核对身份 username。
- `认证 角色 <代号> <中文名> [拒绝 <说明>]`：声明角色代号（与 role 一致）的中文名；他人被拒（403）时说明为「拒绝」后的整句，不写则是「需要<中文名>权限」。
- 接口行 `角色 <代号>` 或 `只许 <中文名>`（等价，中文名按「认证 角色」对回代号）：开着登录时只许当前角色等于该代号的人调，其他人 403；没开登录不查。「只许」写了没声明的中文名，启动记警告，开着登录时谁都 403。角色靠 role 判断，所以需要角色的项目必须有「认证 核对」且返回含 role。
- 开着登录时注入变量 `{current_user}`（用户名）、`{current_role}`（核对得到的 role，没有是空串）、`{auth_mode}`（on/off）；请求体里的同名字段盖不掉它们。

### 项目级开关
- `迁移 只加`（routes/_project.zs 常用，顶层一行）：服务启动前按 entities/ 给已有的 app.db 补缺的表、列、索引，只加不改，绝不 DROP / 重建 / 改已有列；与实体对不上又补不了的（改类型、必填、默认值、主键）只记警告，库原样不动。要改已有列得人工迁移。
- `服务 8091` 或 `服务 8091-8099`：脚本端口范围，可省。
- routes/_project.zs 只放项目级声明（迁移 只加、认证 …），不含接口。
