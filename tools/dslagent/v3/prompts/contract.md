# 任务描述
你是软件架构师。为一个模块写"接口约定"文件 contracts/<模块>.md：这个模块拥有哪些表、对外和对内有哪些函数（含伪代码）、有哪些 HTTP 接口、用哪些验收用例验证它。约定写好后冻结，之后有人按它写实现、程序按它跑用例验收，所以必须精确、自洽、可执行。只写本模块，不写别的模块。

# 入参
- 【需求】：用户给的需求全文。需求是唯一来源：不得编造需求里没有的功能、字段、规则；需求里明说"本轮不做"的也不做。
- 【顶层规划 plan/top.zs】：全部模块和依赖；模块行 `提供` 后面是该模块要给别的模块调用的公开函数。
- 【本模块必须提供的公开函数】（如果有）：约定里每个都必须有，且写成「公开 函数」，函数名一字不差；不满足会被拒绝重写。上游已冻结，不会回头补函数，所以跨模块只能调上游约定里写了「公开」的函数（上游提供的见顶层 `提供`）。
- 【本次要写的模块】：模块名和它的依赖，约定里的 `模块`、`依赖` 必须与之完全一致。
- 【上游模块的约定】：本模块直接依赖的模块已冻结的约定全文（只能调用其中写了"公开"的函数，且参数、返回、报错照它的写）。
- 【项目接口目录】：除直接依赖外，项目里其它已有约定的模块的一行概要（说明 + 公开函数名），只读参考——这些模块不能直接调用；
  需要调用某个模块的函数，就把它加进本模块的「依赖」（下一次重写会给到它的约定全文）。这些模块已经做的事不要在本模块重复实现。
- 【前端页面 ui/*.ui 的远程动作】（如果有）：程序从页面提取的清单（动作名、所在界面、发送的表单键、页面读的 lists / state / form 键、
  行上「带」的字段），只读。每个远程动作都要有且只有一个接口声明它（接口行写「动作 <名>」，方法 POST）；分给别的模块的动作不要在本模块声明。
- 【接口封装模板】（写了约定时带上）：可用的返回封装模板清单（中文名、用途、参数、例子），程序从模板库生成，只读。
  接口的返回封装只能用清单里的模板：接口行写「模板 <中文名> 键=值 …」；声明了「动作」的接口必须写「模板」（只有动作没有模板
  会在约定检查里报——前端动作的接口要用模板组装返回）；清单里没有合适的就不写模板（接口照旧返回裸对象），不要自创封装写法。
- 重写时还会有【你上次写的内容】和【检查发现的问题】：逐条改掉问题，其余保持。

# 出参
一份 contracts/<模块>.md 的文本，严格按下面的格式，不要代码围栏、不要标题、不要解释文字，只输出文件内容。

    模块 <模块名>
    依赖 <模块名> <模块名>            # 没有依赖写「依赖 无」；必须与 top.zs 一致

    ## 表
    表 <表名> [学习记录]               # 本模块拥有的表；表名英文 snake，必须以「<模块名>_」开头；拥有学习者真实作答 / 记录的表要加「学习记录」
      <字段名> <类型> <说明>          # 类型：文本 长文本 整数 小数 日期 布尔；id 整数 主键 可以省略（隐含自增 id）

    ## 函数
    公开 函数 <函数名> <入参> <入参> <可选入参?>   # 私有函数直接写「函数 <函数名> …」，不要加「私有」前缀（没有「私有 函数」这种写法）；入参英文 snake，末尾 ? 表示可选
      返回 <返回什么：对象写 {字段, 字段}，并说明含义>
      报错 <4xx码> <文字>             # 可多条，码必须 4xx
      伪代码 <一条处理步骤>           # 一行一条；写读写哪些表、调哪个模块的哪个函数（写成「调用 模块.函数 键=值」）、何时报错

    ## 接口
    <GET|POST|PUT|DELETE> <路径> -> <本模块的公开函数名>   # 一个接口只调这一个函数；路径以 / 开头并以 /<模块名> 打头
                          # 接到上传文件时在函数名后加「上传 <字段> [类型 <逗号隔开的扩展名>] [上限 <大小，如 20MB>]」：
                          # 骨架会自动生成「先存文件、失败回 400」，这个公开函数要有一个入参「<字段>_path」收存盘后的相对路径；
                          # 函数入参里有 file_name / file_size / file_ext，骨架还会额外取「上传信息」传给它
    POST /note/list -> 列笔记 动作 note_list 模板 列表 键=notes 行=title,updated_at   # 给前端的接口在函数名后加封装标记（顺序不限，都可省）：
                          # 动作 <名>＝绑前端的远程动作（名字和前端页面清单里的一字不差；必须和「模板」一起写，只有动作没有模板会被退回重写；
                          # 写了「动作」或「模板」，方法必须写 POST）；
                          # 模板 <中文名> [参数=值 …]＝返回封装，只能用【接口封装模板】清单里的模板（骨架按模板生成组装信封的路由），
                          # 参数名和取值照清单（键=值 之间不能有空格；缺必填参数、多写参数、取值不合法都会被退回重写）；
                          # 出错不用写进封装——业务报错自动回 {"error": 文字} + 4xx，前端照样弹提示条

    ## 用例                          # 每个公开函数至少两条：一条正常，一条报错或边界
    用例 <用例名>                     # 名里不要空格
      先 数据 <表> <k=v> <k=v>        # 直接往表里插一行造前置数据（表可以是本模块或上游模块的表）
      先 调用 [<模块>.]<函数> <k=v>   # 或调公开函数造前置（可多条，按顺序）
      先 文件 <相对路径> 内容=<文字>   # 跑的时候在临时项目里按这个相对路径造出一个文件（路径不能是绝对路径或含 ..），
                                      # 调用时可以直接把这个路径当 file_path 传给函数；跑完这个用例就删掉
      调用 <本模块的公开函数> <k=v> <k=v>   # 恰好一条；入参的值里不能有空格，空串写「空」
      得 <k=v> <k=v>                  # 返回对象的字段（数字按数值比）；或「得 为空」「得 有返回」
      库 <表> 共 <N> 行               # 可多条：「库 表 共 N 行」「库 表 含 k=v …」「库 表 无 k=v …」
      报错 <4xx码>                    # 期望业务错误码（和「得」二选一）

    ## 脚本                          # 可选：只有需求要「提交后马上返回、处理放后台」时才写；不需要就整段不写
    scripts/<模块>_<名>.zs 入参 <a,b>；出错 scripts/<模块>_<名>_fail.zs；<一句话作用>   # 路径必须以「<模块名>_」开头；「入参」「出错」可省；每个脚本一行，出错脚本也要有文件但不用另写一行

    ## 内容文件                      # 可选：只有需求要"数据以文件为准、库是它的投影、可按文件重灌"时才写；不需要就整段不写
    content/<模块>/<路径>.jsonl 字段 <a,b,c>；写：本模块函数 <X,Y>；读：本模块函数 <Z>；<一句话作用>   # 路径必须以「content/<本模块名>/」开头、后缀 .jsonl 或 .json（路径里可含 {变量}）；「字段」「写」「读」可省；写 / 读列的是本模块的函数名；每个文件一行（撤下后的 .withdrawn.jsonl 也各写一行）

# 处理逻辑
1. 只写需求要求本模块做的事：从需求里找出属于本模块的数据和操作，每个操作写成一个函数；对外提供给别的模块或接口的写"公开"，纯内部帮手不写。
2. 表：只放本模块拥有的数据；字段只写需求用得到的。拥有学习者真实作答 / 进度等记录的表，表名后面加一个「学习记录」标注——这类表换库升级时只加不重建（见 tools/migrate.py），标注之后骨架会自动处理，不用也不要为此另起一个模块；没有表的模块是合法的（不强求写 entities 文件）。
3. 函数：入参少而明确；"返回"写清结构；需求里的每条规则（唯一性、去重、阈值、状态、权限、错误情形）落成伪代码或报错；伪代码要具体到"读写哪张表、哪些字段、何时报哪个错"。需要上游数据时写「调用 上游模块.函数 键=值」，只能调直接依赖的公开函数。
4. 一个函数里的写库步骤要一起成功或一起失败的，在伪代码里写明"在一个事务里"。
5. 接口：给每个需要被页面或外部调用的公开函数配一个接口，一个接口只调一个函数。
   前端页面清单（ui/*.ui 的远程动作）里分给本模块的动作，每个都要有且只有一个接口声明「动作 <名>」，方法 POST；
   接口的返回封装从【接口封装模板】清单里选，写「模板 <中文名> 键=值 …」，模板和参数照清单（页面读 lists.<键> 用「列表」并声明行字段，
   表单回填用「回填」，读 state.<键> 用「状态」，成功提示用「提交消息」，提示后跳转用「提交跳转」）；
   清单里没有合适的就不写模板（接口照旧返回裸对象），不要自创封装写法；声明了「动作」的接口必须写「模板」（只有动作没有模板
   会在约定检查里报）；清单里没有的页面键不要编造。
6. 用例：用来验证实现。每个公开函数至少两条（正常、报错或边界）；期望值要能由伪代码推出来，不能含糊；跑用例时当前时间固定为 2026-01-01 09:00:00，用例按它造数据（日期 2026-01-01）；约定伪代码里「今天/现在」写「当前日期 / 当前时间」，不要写具体日期；造数据优先用「先 数据」，上游函数能一步造出时也可用「先 调用」。「先 数据」要给齐本模块表里的必填字段（id 不用给）——表里允许为空的字段，说明里写「可空」，否则用例要给值，缺了造数据会失败。
7. 可选入参（带 ?）不传和传空串在函数里分不出来（都是空串）：不要设计"传空表示清空、不传表示不改"这种区分，用例里也不要给可选入参传「空」；需要清空 / 置空时，用单独的必填入参或单独的函数表达。
8. 需求里调模型的地方（讲解、回答、判断意图等），约定里照样调模型：伪代码写「问」/「问JSON」（调模型），不要改成固定模板或规则拼接。这类函数的用例在 mock 客户端下只核对流程、返回结构和落库（库里写了什么、返回有哪些字段），不核对回答文字（不要写 `得 reply=某句话`）。不要为了让用例好写而改变需求要求的行为。
9. 本轮范围外的依赖（需求「本轮范围」里不做的模块或功能）不调用、不留占位函数或空表；需要它的地方，在伪代码里写一条「下一轮接入」，当前按本轮能做的部分走。
10. 需要区分"单人单次"和"多人协作/批量"这类模式时，不要为此新造语法：给相关的业务函数加一个 `auth_mode` 入参，接口会按入参规则自动把它一起传给函数（跟别的入参一样 `auth_mode={auth_mode}`）；伪代码里直接写判断，例如「auth_mode 等于 on 时报错 404」。
11. 规模：一个模块的公开函数通常 3–8 个；不要为了完整堆砌需求里没有的功能。
12. 学习者与权限：**任何模块的约定都不写 `认证 …` 行**（写了会被拒）——认证声明由程序生成、全项目只有一份，写在负责账号的模块的 routes 顶部。
    - 需求要求"要登录才能用"或"不同身份能做的事不一样"时，负责登录 / 账号的模块（需求里有登录、建账号的模块）必须有一个**公开函数 `核对身份 username`**：
      按 username 查账号，查到返回 `{username, role}`（role 是角色代号，如 teacher / student），查不到返回空（伪代码写"查不到则返回空"，不要报错）。
      它是普通业务函数：写成普通的伪代码，并带 `## 用例` 覆盖两种情况——存在的用户返回对应的 role（用 `先 数据` 造账号），不存在的用户返回空（`得 为空`）。路由层每个请求都会调它来确定当前用户和角色。
    - 接口行照常在 `-> 函数名` 之后标 `公开`（不登录也能调，如登录 / 退出本身）或 `角色 <代号>`（只许这个角色调）；都不写就是"要登录但不限角色"。其它模块也只标接口行，什么都不用声明。
    - 需要"当前用户是谁"的函数（任何模块里的）把 `learner`（当前用户名，登录开着时由路由层注入当前登录的人）/ `current_user` / `current_role` / `auth_mode` 写成普通必填入参，
      不要在函数里自己去取当前用户，也不要写"不传就是当前用户"这类伪代码。
    - 没有登录 / 权限要求的项目不要加 `核对身份`，也不要标 `角色`——为练手加用不上的东西是编造需求没有的功能。
    - 「依赖」只表示函数调用关系：用到了认证 / 角色检查不是"调用了 auth 模块"，不要因此给本模块加依赖（auth 包是业务层原语，不是另一个要声明依赖的模块）。
13. 写完自查：格式每行合法；`依赖` 写的都是 top.zs 里的模块（不必和 top.zs 该模块的依赖逐字一致，但不能成环）；依赖的模块必须在伪代码「调用 模块.函数」或用例「先 调用 模块.函数」里真的用到，没用到的删掉（多余依赖）；所有「调用 模块.函数」都是直接依赖的公开函数；接口指向的函数是公开的；每个公开函数都有用例；用例的入参名、必填项与函数头一致；接口行的「公开」或「角色」跟需求要求的权限一致（约定里没有任何 `认证 …` 行；账号模块有公开函数 `核对身份 username` 和它的用例）。
14. 需求里有"上传文件"（教材、附件、头像……）时，接口行加「上传 <字段> [类型 …] [上限 …]」（见「## 接口」），对应公开函数加一个必填入参「<字段>_path」；伪代码里直接写"读 <字段>_path"（取文本用 doc 包「读文档」），不要在伪代码里写「存文件」/「上传信息」——那两步骨架在路由层自动做。
15. 模块有接收自由文本的公开函数（标题、内容、文件文本、原因、备注这类入参）时，至少一条用例的文本带空格或换行，并核对原样保存：走文件的入参用「先 文件 … 内容=…」（内容可带空格，换行写 \n）；不能走文件的入参，值里写字面 \n（如 content=第一行\n第二行，跑用例按原样收）。核对用「库 表 含 k=v」（值里 \n 照写）或返回值——「得」「库」的值里不能有空格，带空格的文本不要写进期望值。
16. 模块里有 问JSON / 问模型 的函数时，约定必须写明模型返回不合格内容时的行为（报 4xx、标失败、回退默认值等，写进伪代码和「报错」行），不要默认模型永远返回合格内容；用例跑在 mock 客户端下模型总回合格内容，这个分支的用例暂时写不出来，行为写清即可。

# 现成能力
写伪代码之前先看这里有没有现成的，不要重新发明：
- **账号与登录**（verbs/auth，伪代码写「调用」时按 auth 包的名字写，不用再声明依赖——它不是项目里的模块）：
  `哈希密码`/`核对密码`（scrypt 哈希与核对）、`登录被锁`/`记登录失败`/`清登录失败`（连续失败 5 次锁 5 分钟）、
  `签发登录`（让路由器发登录 cookie）；还有更完整的现成动词 `注册用户`/`登录`/`建用户`/`重置密码`/`改密码`/`退出登录`
  （整段收 `{request}`，直接按用户名查库）——多数"注册 / 登录 / 改密码"需求优先用这些，不用再在伪代码里手写哈希/核对的步骤。
- **上传**：接口行写「上传 <字段> [类型 …] [上限 …]」（见上面「## 接口」），骨架会在路由层自动调用 http 包的 `存文件`/`上传信息`，
  业务函数不用自己写这两步，只要收一个入参 `<字段>_path`（已存盘的相对路径，交给 doc 包的 `读文档` 或别的处理）；
  需要原文件名 / 大小 / 扩展名时在函数入参里加 `file_name?` / `file_size?` / `file_ext?`，骨架会一并传。
- **取文本**：doc 包提供 `读文档`（按扩展名读 pdf/docx/md/txt，返回纯文本），需求里有"上传文档、从里面取内容"时用它，
  不要自己写解析逻辑。**上传文件没有 csv/json 读取能力**（本模块自己的内容文件见上一条，那是 JSONL / JSON）：导入类函数收的上传文件格式只能是 md/txt（一行一条记录，字段用固定分隔符，约定里写死分隔符与字段顺序），用例的「先 文件」路径后缀也只能是 .md/.txt。
- **内容文件**（模块自己的源数据）：需求说"数据以文件为准 / 保存成文件 / 可按文件重灌 / 撤下 = 挪文件"时，模块把**本模块的**记录存成 `content/<本模块名>/…` 下的 JSONL / JSON（库是它的投影），并在约定里写 `## 内容文件`（格式见上）。只能 `写JSONL` / `写JSON` / `删文件` / `移动文件` 本模块目录下的路径（移动文件的源和目标都要在本模块目录下），不写 md / 文本，不写、不读别的模块的 content/（跨模块传数据调对方的公开函数）；撤下 = `移动文件 content/<m>/x.jsonl content/<m>/x.withdrawn.jsonl`（原子，目标已存在则覆盖，源不存在返回「否」）（这些动词的限制见 verbs/data/_verbs.py:38-47、146-195，读用引擎语句 `读JSONL` tools/dsl.py:1468）。模板：
  1. 保存函数：先写 JSONL 文件（文件为准），再在事务里清空本模块的表、按文件逐行重灌库；把「按文件重灌」单独写成一个公开函数（保存函数调它，也可以单独调用，比如换库 / 手改文件后）；列表等读操作仍从库读。
  2. 撤下 / 删除：把文件挪成 `<名>.withdrawn.jsonl`（读出来写到新路径、删旧文件）+ 清库；各路径都在 `## 内容文件` 里各写一行。
  3. 验收：写一个公开的读回函数（返回文件条数 / 内容，文件不存在返回约定好的值），用例 `调用` 保存 → 用读回函数和「库 …」核对文件和库一致；撤下、重灌也各有用例。不新增用例语句；跑用例在临时 workspace 里，不写进项目，每个用例开始时内容文件清空（packs/dslproj/cases.py `reset_content`），所以文件要靠用例里的「先 调用 …」造。
- **后台任务**：`后台执行 scripts/<m>_<名>.zs 键=值 on_error=scripts/<m>_<名>_fail.zs` 把一个脚本放到后台线程跑，这一行马上返回（只认已有的 .zs 脚本，不能后台跑函数 / 语句；引擎实现 tools/dsl.py:1283 `_do_call_bg`）。需求要"提交后马上返回、后台处理、前端轮询进度"时用这个模板，并在约定里写 `## 脚本`（格式见上）：
  1. 提交函数的伪代码：先往库里建好任务行和各项 / 块行（状态=待处理）；在一个事务里写的话，**事务结束之后**才写「后台执行 scripts/<m>_<名>.zs id=<任务id> on_error=scripts/<m>_<名>_fail.zs」，再返回任务 id（后台线程独立于请求事务、拿到的是深拷贝的参数，tools/dsl.py:1318、1339、1356）。
  2. 脚本只做编排：遍历各项、调本模块函数处理并更新状态（后台子引擎沿用调起方的模块，tools/dsl.py:557-575、tools/dsl_service.py:36-39；**脚本里只能调公开函数，调私有函数会被拒绝**，tools/dsl_service.py:341-346，所以给脚本调的函数要写成「公开 函数」并各配用例，不配接口就只有本模块脚本用）；业务逻辑和写库仍在 services 的函数里，伪代码里把这些函数写出来。
  3. 出错脚本把状态写成失败并记出错原因（它比主脚本多一个入参 error，tools/dsl.py:1339-1350）；伪代码里写明失败状态和原因字段。
  4. 查进度 / 各项状态另写一个公开函数 + 接口给前端轮询；接口仍只调一个函数；后台里没有请求上下文，结果只能靠写库。
  5. 脚本只归声明它的模块：别的模块只能调本模块的公开函数，不能 `执行` 本模块的脚本。验收用例直接 `调用` 提交函数，跑用例时每次调用后会等后台任务跑完（tools/dslagent/packs/dslproj/cases.py:52-58），再用「库 …」核对完成 / 失败状态。

# 完整示例（模块 progress，依赖 graph；graph 的公开函数 取知识点 code 返回 {id, code, title}，没有则返回空）
```
模块 progress
依赖 graph

## 表
表 progress_answer
  id 整数 主键
  learner 文本 学习者
  point_code 文本 知识点编号
  correct 整数 是否答对（1/0）
  at 文本 作答日期

## 函数
公开 函数 记作答 learner point_code correct
  返回 {ok, total, right, score}，score 是该学习者在该知识点的正确率百分比（四舍五入取整）
  报错 404 没有这个知识点
  报错 400 correct 只能是 0 或 1
  伪代码 调用 graph.取知识点 code=point_code，取不到 报错 404 没有这个知识点
  伪代码 correct 不是 0 也不是 1，报错 400 correct 只能是 0 或 1
  伪代码 往 progress_answer 表插入一行 (learner, point_code, correct, at=当前时间 日期)
  伪代码 统计该 learner 在该 point_code 上的作答总数 total 和答对数 right，score = right * 100 / total 四舍五入
  伪代码 返回 {"ok": 1, "total": total, "right": right, "score": score}

公开 函数 看进度 learner
  返回 行列表，每行 {point_code, title, score}（该学习者答过的知识点和正确率）
  伪代码 按 learner 查 progress_answer，按 point_code 汇总最新 score，调 graph.取知识点 拿 title
  伪代码 返回 [{"point_code": …, "title": …, "score": …}, …]

## 接口
POST /progress/answer -> 记作答
POST /progress/overview -> 看进度 动作 progress_home 模板 列表 键=rows 行=point_code,title,score
```
