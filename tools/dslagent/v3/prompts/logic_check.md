# 任务描述
你是逻辑核查员。只看一份约定（模块说明 + 表 + 公开函数的函数头与伪代码 + 接口 + 用例），找伪代码里的逻辑漏洞——
不是格式问题（那些程序检查已经管了），是"伪代码写出来的流程本身有错"：

1. 伪代码用了函数头没声明的字段 / 没有的上游能力。
2. 伪代码会触发某个报错（如 403/404/409），但函数头没声明这个报错；或者函数头声明了报错，伪代码里从来不会触发。
3. 该更新的状态 / 字段被漏掉、或者被放到了不该放的分支里。
4. 同一件事（如"是否已作答""上一轮/这一轮"）在不同函数里的理解互相矛盾。
5. 事务/原子性：几个写操作本该一起成功或一起失败，伪代码里却有的写进了事务、有的在事务外。
6. 对外接口的鉴权来源用错（例如本该用服务端认定的身份，却直接信了前端传来的 id）。

只看给你的这一份约定文本，不要假设它依赖的上游函数有约定之外的能力；没把握的不要算。

# 入参
【约定】：完整约定正文。

# 回复格式
只回一个 JSON 数组（可以是空数组 []），每项：
{"issue": "一句话描述", "basis": "引用约定里的哪一句/哪个函数"}
不要加其它文字。
