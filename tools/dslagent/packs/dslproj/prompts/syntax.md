## DSL 项目写法速查（实体、查询、业务层、接口）
- 实体 entities/<模块>.entity（建表）：
```
实体 answer 作答
  字段 learner 文本 必填 索引 学习者
  字段 correct 布尔 必填 默认 否 对错
  字段 at 文本 必填 默认 now 时间
结束
```
  类型：文本 长文本 整数 小数 日期 布尔 枚举（枚举写 枚举 a,b,c）；旗标：必填 唯一 索引；`关联 <实体>`、`默认 <值>`、`主键 a b`、`唯一 a b`。一个实体 = 一张表，隐含自增 id（有 主键 就不加）；每个实体以「结束」收尾；约定「## 表」里每个表名都要有同名实体；只写本模块拥有的表。约定要求唯一的字段必须写 `唯一` 旗标（多列合起来用行首 `唯一 a b`），只把「唯一」写在说明文字里不生效、建表没有 UNIQUE、库不拦重复；核查时缺旗标算问题（代码先查后插也挡不住并发和直接写库）。
- SQL queries/<名>.sql：一个文件一条语句，参数 `:名`；参数传进来都是字符串，数值比较 / LIMIT 要 CAST，如 `CAST(:n AS INTEGER)`。文件名以模块名开头（queries/progress_answer_insert.sql）。
- 业务 services/<模块>.zs（所有逻辑写在这里）：
```
业务 progress
  依赖 graph                 # 要调用哪些别的模块的公开函数；不写就不能调（和约定的「依赖」一致）
  用包 db                    # 本文件函数共用的包

  公开 函数 记作答 learner point_code correct answer?
    设 p = 调用 graph.取知识点 code={point_code}
    如果 {p} 为空
      报错 404 没有这个知识点
    结束
    事务 app.db
      设 n = 写库 app.db progress_answer_insert learner={learner} point_id={p.id} correct={correct}
    结束
    返回 {"ok": 1}
  结束

  函数 内部帮手 learner         # 不写「公开」= 只给本模块用
    设 total = 查一值 app.db progress_answer_count learner={learner}
    返回 {"total": {total}}
  结束
结束
```
  函数是独立作用域：里面只有入参，要什么当入参传（可选入参 `名?` 不传是空串）。`返回 值`（对象写 JSON，值里可嵌 {变量}）交出结果；`报错 4xx 文字` 是业务错误（沿调用链到接口变成 HTTP 码 + {"error": 文字}）。
  调用：`设 r = 调用 模块.函数 键=值 …`（同模块可只写函数名）；接住业务错误加 `出错时 e`（`{e.code}` `{e.error}`，没出错 `{e}` 是空串）。模型返回的内容不合格（问JSON 格式不对：不是合法 JSON、缺字段、类型不对）也接得住（`{e.code}` 是 502）；脚本写错、加载错不会被接。问JSON 语句自己在**末尾**写 `出错时 e` 也能接（`问JSON j = 提示词 格式 a:文本 出错时 e`，没有「格式」就 `问JSON j = 提示词 出错时 e`；只认末尾，接住时 j 是空串）。几个写操作要一起成功或一起失败，包在 `事务 app.db … 结束` 里。
  后台任务：`后台执行 scripts/<m>_<名>.zs 键=值 on_error=scripts/<m>_<名>_fail.zs` 能在业务函数里写（只认已有的 .zs 脚本，不能后台跑函数；tools/dsl.py:1283 `_do_call_bg`）。模块可以新建 `scripts/<本模块名>_*.zs`（范围里已放行；约定写了「## 脚本」的脚本文件必须都建出来，不能多建没声明的）。按约定的伪代码写，模板：
  ① 业务函数里先写库建好任务行 / 块行（状态=待处理），**事务结束之后**再 `后台执行 …`，随后返回（后台线程独立于请求事务、参数深拷贝，tools/dsl.py:1318、1339）；
  ② 脚本只做编排（遍历、调函数），读写状态都调本模块的函数（`调用 <m>.函数 …`，tools/dsl.py:557-575、tools/dsl_service.py:36-39）；脚本里只能调**公开**函数（私有函数只有业务函数里能调，tools/dsl_service.py:341-346），约定里给脚本调的函数都是「公开 函数」，照着写成公开；
  ③ fail 脚本把状态写成失败并记 `{error}`（比主脚本多一个 error 变量，tools/dsl.py:1339-1356）；
  ④ 后台里没有请求上下文，结果只能写库；接口仍只调一个函数（进度另写公开函数 + 接口）；
  ⑤ 本模块的脚本只由本模块的函数执行，不要 `执行` 别的模块的脚本（加载检查会报）；验收用例本来就等后台跑完（cases.py:52-58）。
  内容文件：模块可以把**本模块的源数据**存成 `content/<本模块名>/…` 的 JSONL / JSON（文件是源，库是投影）：业务文件顶部的 `用包` 行带上 data（如 `用包 db data`），函数里写 `写JSONL content/<m>/x.jsonl {rows}` / `写JSON …` / `删文件 …` / `移动文件 源 目标`（verbs/data/_verbs.py:146、155、168、181，路径限工作目录内 :38-47；移动文件父目录自动建、目标已存在覆盖、源不存在返回「否」），读 `读JSONL 变量 = content/<m>/x.jsonl`（tools/dsl.py:1468）、`存在 路径`（:100）。content/<本模块>/ 不用也不能在范围里建文件——文件是函数运行时写出来的，STRICT_SCOPE 只拦你写代码，不拦运行期写盘。规则（加载检查 / 比对约定会查）：
  ⓐ 写 / 删 / 移动（源和目标都算）的路径直接写成以 `content/<本模块名>/` 开头的字面量（变量只放后面，如 `content/<m>/{series}.jsonl`）；不写别的模块的目录、content/ 以外的路径、不写 md / 文本；**不读别的模块的 content/**，跨模块要数据调对方公开函数。
  ⓑ 用到的 content 路径都要在约定「## 内容文件」里有声明，路径照约定一字不差。
  ⓒ 保存 = `写JSONL` 文件 → `事务 app.db … 结束` 里清空本模块的表、按文件逐行重灌库（约定里的「按文件重灌」公开函数，保存函数调它）；撤下 / 删除 = 挪文件（`移动文件 content/<m>/x.jsonl content/<m>/x.withdrawn.jsonl`）+ 清库；读列表仍从库读。
  ⓓ 验收用例本来就是 `调用` + 库核对，文件内容靠约定里的公开读回函数核对；跑用例在临时 workspace 里（cases.py `run` 的 copytree），每个用例开始前清空本模块及上游的 content/<模块>/（`reset_content`），不会写进项目。
  条件：等于 不等于 为空 不为空 包含 大于 小于 不小于 不大于 开头是（也可 > < >= <= == !=）；组合用 且 或 非。算数：`设 n = 计算 {a} * 100 / {b}`。取时间：`设 now = 当前时间`。`{x 或 默认}` 取变量，空时用默认。
  db 包动词：`查一行 app.db 查询名 键=值`（没有则空）、`查一值 …`（单列）、`查询 app.db 查询名 键=值`（多行列表，可 遍历）、`写库 app.db 查询名 键=值`（键=值 最多 8 对）。值的空格规则：字面量值不能带空格（会被按空格切开，引擎报错）；值整个是 `{变量}` 时内部空格 / 换行原样保留（核查时「`键={变量}` 且变量可能含内部空格」不算问题）；值首尾有空白引擎直接报错，字面量里多出「词=值」碎片也报错——值要保留首尾空白或要传整条记录时改用 `查询表` / `查一行表` / `查一值表` / `写库表`（写法 `动词 app.db 查询名 {结构}`，按名取参、不按空格切，没有 8 对限制；`写库表` 返回影响行数）。查询名 = queries/ 下的文件名（不含 .sql）。
- 接口 routes/<模块>*.zs（文件名以模块名开头）：只收请求、调一个函数、返回，一个接口只调约定里写的那个函数：
```
接口 POST /progress/answer
  设 r = 调用 progress.记作答 learner={learner} point_code={point_code} correct={correct}
  返回 {r}
结束
```
  请求字段直接是变量（如 `{learner}`），可选入参没传时就是空串。
- 函数头（名字、入参、公开与否、依赖）必须和约定一字不差，程序会比对；约定文件 contracts/ 不能改，验收用例由程序按约定里的「## 用例」跑，不要自己写别的测试。
