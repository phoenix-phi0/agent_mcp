你是项目架构师。这是 modular 建项目的第一步「顶层规划」：只看整体，不涉及任何文件，不写 sql/接口/界面。读需求和「能力清单」（现成 Python 动词，按包分），用下面的 DSL 写出规划文件 plan/top.zs 的全文（不要围栏、不要解释）。
语法：中文关键字、一行一件事；`项目 … 结束`、`主流程 … 结束` 是块，块用 `结束` 收尾；整行以 # 开头是注释；一行里用空格隔开各项（所以名字、角色、步骤都是不含空格的一个词）。
完整示例：
```
# 顶层规划
项目 让学生按课文做题、看掌握进度，老师能看全班情况
  使用者 teacher student 多人
  横切 账号 private 模板，账号由 gen 统一生成，不另建账号表；teacher 管题库，student 做题；学生不能自己注册，账号由教师创建
  横切 调模型 common 开放题讲解
  横切 后台任务 每晚汇总掌握进度
  横切 导入 题库从 jsonl 导入
  约束 老库只加表加列，不改不删
结束
模块 quiz 题库、出题、判题
模块 progress 掌握进度统计 依赖 quiz
共用流程 quiz_judge 归 quiz 用于 progress
主流程 学生做题 student 经过 quiz progress
  步骤 选课 做题 交答案 看进度
结束
主流程 老师看全班 teacher 经过 progress
  步骤 看全班进度
结束
构建顺序 quiz progress
```
各行含义（程序逐项校验，不过会带报错——带行号和原行——让你重写）：
- `项目 <目标一句话>` 块：里面 `使用者 <角色…> 单人|多人`（角色＝英文小写 snake，最后一项是 单人 或 多人；需求提到登录、账号、老师/学生等身份就给角色，注册默认角色放最后；单人无登录只写 `使用者 单人`）；`横切 账号 <一句话>`（private 时账号表由 gen 统一生成，不要在模块里再建账号；需求说学生不能自己注册、由教师建号的，这里要明写「学生不能自己注册，账号由教师创建」，程序据此关掉公开注册 /auth/register；无登录写「无账号」）；`横切 调模型 <包> [用在哪]`（包必须在能力清单里，可写多行）；`横切 后台任务 <一句话>`（可多行）；`横切 导入 <一句话>`；`约束 <一句话>`（不属于某个文件的全局约束，可多行）。
- `模块 <名> <说明> [依赖 <模块…>]`：名＝英文小写 snake、全项目唯一；说明不含「依赖」二字；依赖＝它要用到的别的模块（不许成环、不许依赖自己）。模块按业务边界切（一个模块管一块数据和它的业务），别切得太碎，通常 2~6 个。
- `共用流程 <流程名> 归 <模块> 用于 <模块…>`：被多个模块用到的业务流程放一个归属模块；用于里的模块必须（直接或间接）依赖归属模块。没有就不写这行。
- `主流程 <名> <角色|-> 经过 <模块…>` 块，里面 `步骤 <步骤…>`（一个词一步，可多行）；角色不限写 `-`；经过的模块必须是上面写过的模块。
- `构建顺序 <模块…>`：所有模块按依赖排好的顺序（被依赖的在前），不多不少，只写一行。
只做需求里有的东西，不发明需求外功能。
