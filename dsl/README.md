# 干净的 DSL 环境

拿来试语法、写动词、跑回归。不读 `config.json`，不碰 `workspace`，
不加载日语教学的动词包——在这儿折腾坏了不影响那边。

## 跑起来

```
cd dsl
py run.py scripts/hello.zs      用假客户端跑一遍语法巡览
py run.py -e "打印 你好"
py run.py --verbs               看有哪些动词
py run.py --help-dsl            看完整语法
```

常用开关：

| 开关 | 作用 |
| --- | --- |
| `--real` | 走真实模型。默认是假的，不花额度 |
| `-v` | 边跑边打印，看得到执行顺序 |
| `--calls` | 列出每次模型调用的提示词，确认插值结果 |

## 为什么默认是假客户端

每跑一次都真发请求的话，写语法时不敢反复跑，调试就束手束脚。

`EchoClient` 把提示词回显成 `[回声] xxx`——**看得见变量插值后的实际内容**，
这正是调试时想看的。真正要验证模型输出质量时才加 `--real`。

写确定性测试用 `ScriptClient(["第一次","第二次"])`，按预设依次返回。

## 目录

```
run.py           入口
client.py        假客户端（EchoClient / ScriptClient）
verbs/
  common/        基础动词：算术、文本、JSON、文件、调试
scripts/
  hello.zs       语法巡览，所有语句走一遍
work/            脚本读写文件的落点，随便删
```

## 加动词

在 `verbs/common/_verbs.py` 里写个函数，重跑就生效：

```python
@reg.verb("两数相乘")
def 相乘(甲: str, 乙: str) -> str:
    return str(float(甲) * float(乙))
```

参数按位置绑定，**值里不能有空格**——要传含空格的内容，先用「设」存进变量
再用 `{变量}` 传。

想分包就在 `verbs/` 下新建目录，里面放 `_verbs.py`，会自动加载。

## 跟主项目的关系

引擎（`tools/dsl.py`、`tools/verbs.py`）是共用的，**不复制一份**。

两份引擎意味着语法改一处要改两边，行为不一致的 bug 极难查。不共用的是
*环境*：客户端、动词包、工作目录都是这里自己的。

`run.py` 启动时往上找含 `tools/dsl.py` 的目录并加进 `sys.path`，所以这个
文件夹放在项目里哪一层都能跑。

## 已知的语法边界

写脚本时容易撞上的几条：

- 动词参数**不能含空格**，`当` 之类的条件值也是
- `判定` 的分支输出不能含空格：`正确→○ 答对了` 只会捕获 `○`
- 全角逗号在**列表位置**是分隔符，在正文里原样保留
- 关键字后紧跟汉字时不算关键字，所以 `打印机 状态` 不会被当成 `打印`
- **未知动词会静默透传**：`设 x = 打错的动词名 参数` 不报错，变量得到的是
  字面字符串。写完先 `--verbs` 对一下名字，或者空跑看输出里有没有残留的
  中文动词名
